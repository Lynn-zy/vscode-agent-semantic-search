# 「未就绪」只能靠返回文本判定

底层语义检索不是本扩展的代码：它经 `vscode.lm.invokeTool` 调用，中继端口 `ToolRawResult` 只暴露 `content` 部件，没有任何可用于判断服务是否就绪的结构化字段。因此 `not-ready` 的判定只能基于规整后的文本，并且必须同时设上界——取「包含不可用提示句」且「去首尾空白后不超过单句通知体量（200 字符）」两个条件。只取包含判定会把真实检索结果误判为未就绪：本仓库的 `semanticSearchRelay.ts` 自身就含有该提示句字面量，检索到它时会被当成不可用通知，而真实检索结果必然远超单句通知的体量。
